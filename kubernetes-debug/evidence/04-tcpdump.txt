### Шаг 4. tcpdump в отладочном контейнере
### Дата: 2026-09-06 22:58:48 +05

### Команда захвата (терминал A):
kubectl exec nginx-distroless -c debugger2 -- tcpdump -nn -i any -e -c 40 port 80
  -nn      не резолвить имена хостов и номера портов
  -i any   слушать все интерфейсы network namespace pod'а
  -e       печатать заголовки канального уровня (MAC-адреса)
  -c 40    остановиться после 40 пакетов (для неинтерактивной записи в файл)

### Команда генерации трафика (терминал B):
POD_IP=$(kubectl get pod nginx-distroless -o jsonpath='{.status.podIP}')   # = 10.244.0.115
kubectl run curl-load --rm -i --restart=Never --image=curlimages/curl --image-pull-policy=IfNotPresent -- \
  sh -c "for i in 1 2 3 4 5; do curl -sS -o /dev/null -w \"req\$i: %{http_code}\n\" http://$POD_IP:80/; done"

### Почему это работает:
Все контейнеры pod'а, включая эфемерные, разделяют один network namespace,
поэтому tcpdump в debugger2 видит трафик контейнера nginx как свой собственный.
Для захвата нужен CAP_NET_RAW — он даётся профилем --profile=netadmin.
