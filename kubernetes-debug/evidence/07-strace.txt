### Шаг 7 (задание со *). strace корневого процесса nginx в distroless-контейнере
### Дата: 2026-09-06 23:17:48 +05

================================================================
ЧТО НУЖНО ДЛЯ strace — 4 условия
================================================================
1) Общий PID namespace с целевым контейнером — флаг --target=nginx.
   Без него в отладочном контейнере не видно чужих процессов и ptrace невозможен.
2) Право трассировать процесс: CAP_SYS_PTRACE (--profile=sysadmin даёт privileged
   со всеми capabilities) ЛИБО kernel.yama.ptrace_scope=0 на ноде.
   Это ИЛИ, а не И — см. матрицу ниже.
3) Отладочный контейнер должен работать от root (uid=0). Трассировка процесса
   другого пользователя без CAP_SYS_PTRACE запрещена в любом случае.
4) strace должен быть в образе отладочного контейнера (nicolaka/netshoot — есть;
   в самом distroless-образе его, разумеется, нет).

Дополнительно (не про права, но про практику):
5) Эфемерный контейнер надо запускать как '-- sleep infinity', а НЕ как /bin/bash.
   Иначе при выходе из интерактивной сессии контейнер завершается (exitCode 130),
   а эфемерные контейнеры нельзя перезапустить или удалить — имя занимается навсегда.
   Так были потеряны имена 'debugger' и 'strace-debugger'.

== восстанавливаем исходное значение ноды ==
kernel.yama.ptrace_scope = 1

ИТОГ МАТРИЦЫ (цель — nginx master, PID 1, uid=root; трассировщик тоже root):
  ptrace_scope=1 + без CAP_SYS_PTRACE -> EPERM (Yama разрешает трассировать
                                          только своих потомков)
  ptrace_scope=1 + CAP_SYS_PTRACE     -> РАБОТАЕТ (capability обходит Yama)
  ptrace_scope=0 + без CAP_SYS_PTRACE -> РАБОТАЕТ (классические правила: одинаковый uid)
  ptrace_scope=0 + CAP_SYS_PTRACE     -> РАБОТАЕТ
Значение ноды восстановлено в исходное kernel.yama.ptrace_scope=1,
поэтому рабочий вариант здесь — --profile=sysadmin.

================================================================
КОМАНДЫ
================================================================
# 1. Эфемерный контейнер с privileged и общим PID namespace:
kubectl debug nginx-distroless --image=nicolaka/netshoot:latest \
  --image-pull-policy=IfNotPresent --target=nginx \
  --container=stracer --profile=sysadmin -- sleep infinity

# 2. Трассировка. ВАЖНО: master-процесс (PID 1) сам запросы НЕ обрабатывает —
#    он висит в rt_sigsuspend. Работу делает worker, поэтому трассируем все PID nginx:
kubectl exec nginx-distroless -c stracer -- sh -c 'PIDS=$(pgrep nginx | sed "s/^/-p /" | tr "\n" " "); strace -f $PIDS -tt -T -s 128'
#    -f  следовать за потомками   -tt  время с микросекундами
#    -T  длительность каждого вызова   -s 128  длина печатаемых строк

# 3. Параллельно — генератор трафика:
POD_IP=$(kubectl get pod nginx-distroless -o jsonpath="{.status.podIP}")
kubectl run curl-loop --restart=Never --image=curlimages/curl -- \
  sh -c "while true; do curl -sS -o /dev/null http://$POD_IP:80/; sleep 1; done"
